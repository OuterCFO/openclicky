What happens when you ask?

Choose a step. This is an explanation, not a live connection to the app.

Seeing your screen

The screen-answer path requests fresh screen context for each submitted question. Capture can be prewarmed locally. The model receives attached snapshots, not an uninterrupted movie of everything you do.

A screen can change after capture. Old answers and coordinates can become stale.

Pointing is a local output

The model returns text and tags such as a target position or rectangle. OpenClicky interprets them, maps screenshot pixels to display coordinates, and animates the AI cursor or draws a highlight.

The compact answer follows the AI pointer. It does not move your real mouse.

Conversation
Its own thread

OpenClicky creates its own AI conversation through Codex app-server. Sharing a login does not import this Codex chat or all your ChatGPT conversations.

Same account does not mean same memory.

Think of your login as the membership card. Each app still decides which notes, images, instructions, and conversation to give the AI.

Where does the computation happen?

Your Mac handles dictation integration, capture, layout, local files, the Codex client, and pointer animation. OpenAI performs model inference remotely. This setup does not download or run a local LLM.

Wispr is a separate transcription product with its own account and service behavior. Its processing is not covered by the ChatGPT login.

What is “Codex app-server”?

A local program with a messaging interface. OpenClicky asks it to start a conversation, submit a turn, and stream the reply. It manages authentication and communicates with the model service. “Local server” describes where the bridge runs, not where the AI model runs.

Official app-server documentation
Could an API key change billing?

Yes. The code also contains paid API routes. The OpenAI branch prefers the Codex client, then can fall back to the OpenAI API if a key is configured. The dedicated Codex branch uses the Codex session directly. A ChatGPT subscription does not pay for Anthropic or other providers.

Explore what survives

Exactly how much local history and memory?

The tutor saves its latest 24 transcript entries locally. A user message and an assistant message count as separate entries. The prompt reconstructs recent exchanges; it is not an unlimited archive. The memory helper includes up to 6,000 characters by default. The tutor’s remote thread is kept while running but starts fresh after restart; saved local context helps reconstruct continuity.

Can I switch the AI?

Partly. OpenClicky has several provider adapters, but it is not a universal plug-in for any model or any subscription.

Changing the model in the Codex app does not automatically change OpenClicky.

OpenClicky stores its own model choices. Both the tutor model preference and the agent model preference currently read gpt-5.6-sol. Supported models can be selected through OpenClicky’s settings. Only models your backend can access will work; a catalog entry alone is not proof of account access.

One panel, separate sessions

The everyday companion

Command + Option opens the compact input and starts Wispr. Submit closes it, asks the current session, then shows the AI pointer and answer.

History expands the same panel. The tutor’s menu bar task icon opens its saved exchanges directly.

Escape or × dismisses the reply and active highlights without deleting the conversation.

The latest adaptive-input and history build compiled and installed, but its live appearance still needs your test.

A separate agent task

An explicitly created task has its own transcript and model session. Clicking its menu bar icon opens that task’s history in the shared panel.

Follow-ups from that panel target that task. Command + Option retains the selected task while the app runs. Clicking the tutor task icon switches back to the everyday tutor.

The tutor has a read-only execution policy. Explicit agents have broader tools and may use workspace-write or full-access policies. They are different execution paths.

What would make it a fully informed workflow companion?

A maintained context bridge: load the lab’s workflow knowledge, load your current learning checkpoint, and give each tutor turn a short up-to-date summary with source dates. That would explicitly connect the curriculum rather than rely on the screen or your account to imply it.
